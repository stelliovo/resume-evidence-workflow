# Resume Evidence Workflow

一套面向各类 Agent 和对话式 AI 的完整简历工作流，覆盖职业经历盘点、JD 匹配、简历改写和投递版本生成。

它先帮助用户发现容易被忽略的经历与价值，建立可复用的 Markdown 经历证据库；获得目标 JD 后，再解读岗位要求、匹配证据，并从当前 Agent 已安装的简历 Skill 中选择最适合该市场、行业、岗位和语言的一项完成定向改写。

## 主要特点

- 在没有 JD 时也可以先盘点经历，不把所有深挖推迟到投递阶段。
- 用自然、具体的问题帮助用户回忆，内部保留专业判断。
- 区分事实、估计、解释和简历呈现选择，不凭空补充经历。
- 先制作 JD—证据匹配矩阵，再决定简历的强调、压缩或改写方向。
- 根据 JD 选择当前 Agent 中更合适的简历 Skill；没有合适 Skill 时提供保守改写或第三方 Skill 候选。
- 在改写阶段发现的新事实、更新数据和项目进展会同步回经历库，并向用户说明。
- 深挖时会适度询问协作、困难、决策、复盘等行为面试常见内容，保留下来的经历也可以辅助后续面试准备。

## 怎么使用

### 方法一：把仓库链接交给 Agent

复制本仓库链接，直接告诉 Agent：

```text
请读取并使用这个仓库里的简历工作流：<仓库链接>
```

如果 Agent 支持从 GitHub 安装 Skill，也可以让它克隆或安装整个仓库：

```bash
git clone <仓库链接>
```

安装时保留仓库原有目录结构即可。

### 方法二：上传给对话式 AI

下载仓库后，向对话式 AI 上传：

- `SKILL.md`
- `references` 文件夹中的全部 Markdown 文件

然后告诉它：

```text
请完整阅读 SKILL.md 和 references 中的文件，并按照这套工作流帮助我盘点经历、匹配 JD 和改写简历。
```

`agents/openai.yaml` 主要用于支持 Skill 配置的 Agent；普通对话式 AI 不需要上传。`README.md` 和 `LICENSE` 也不是运行工作流所必需的。

## 使用示例

```text
请使用这套工作流，先帮我把现有简历里的经历逐段盘点清楚，建立 Markdown 经历库。现在还没有确定 JD。
```

```text
请使用这套工作流，根据这份 JD 检查我的经历库，先给出 JD—证据匹配矩阵，再选择当前 Agent 里最合适的简历 Skill 完成改写。
```

语音输入或转写文本也可以直接作为经历叙述。识别不清的姓名、日期、数字和专有名词应先确认，不能把转写猜测直接当成事实。

## 输出与注意事项

- 经历库默认保存为 Markdown；HTML、Word 或其他格式按用户需要另行生成。
- 删除经历或要点前必须取得用户同意。
- 最终格式由用户要求及所选简历 Skill 决定。
- README、示例和测试材料不得使用真实用户的个人信息或可识别经历组合。

## 仓库结构

```text
resume-evidence-workflow/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
```

具体工作流、证据结构、提问停止规则、语音输入处理和简历 Skill 路由规则均在 `SKILL.md` 及其按需引用的文档中。
